# HolaVoca v2.0 Transition & GitHub Workflow Guide

## 1. Branching Strategy (Parallel Management)

To keep v2.0 development organized while allowing continuous improvement for v1.3.x:

- **`main`**: The current stable production branch (latest release).
- **`v1.3-maintenance`**: Dedicated branch for ongoing fixes and minor improvements to the 1.3 line.
- **`develop`**: The main integration branch for v2.0 development.

### Workflow

- **Maintenance (v1.x)**: Work on `v1.3-maintenance`. When ready, merge back to `main`.
- **v2.0 Features**: Create `feature/v2-*` branches from `develop`. Merge into `develop`.
- **Cross-Porting**: Any critical fixes in `v1.3-maintenance` should be merged into `develop` as well.

---

## 2. Versioning & Tagging

Use **Git Tags** to mark significant releases.

- **v1.3.14**: Final base state before major v2.0 architectural changes.
- **v2.0.0-alpha.x**: Early integration phases for the new logic.

---

## 5. Immediate Next Steps for v2.0

1. **Tag current state**: Create `v1.3.14` tag on `main`.
2. **Initialize Maintenance**: Create `v1.3-maintenance` branch from `main`.
3. **Initialize v2.0**: Create `develop` branch from `main`.
4. **Update v2.0 Metadata**: On `develop`, update `package.json` to `2.0.0-alpha.1`.
