# HolaVoca v2.0 Transition & GitHub Workflow Guide

Moving to v2.0 is a major milestone. This guide outlines how to use GitHub professionally to manage this transition while maintaining stability.

## 1. Branching Strategy (The "Git Flow" approach)

To keep v2.0 development organized and separate from the stable v1.x code:

- **`main`**: The stable branch. Contains the current production version (v1.x).
- **`develop`**: The main integration branch for v2.0. All new features for 2.0 will be merged here first.
- **`feature/v2-*`**: Short-lived branches for specific 2.0 features (e.g., `feature/v2-dynamic-levels`, `feature/v2-pos-logic`).

### How to execute

1. **Create `develop`**: `git checkout -b develop`
2. **Work on features**: `git checkout -b feature/v2-feature-name`
3. **Merge to `develop`**: PR (Pull Request) from `feature/*` to `develop`.
4. **Final Release**: After testing, merge `develop` into `main`.

---

## 2. Versioning & Tagging

Use **Git Tags** to mark significant states in history.

- **Current State**: Tag as `v1.3.14` (Stable).
- **v2.0 Milestones**: Use tags like `v2.0.0-alpha`, `v2.0.0-beta` as we progress.

### How to execute

- `git tag -a v1.3.14 -m "Final v1.3 release with full planning for v2.0"`
- `git push origin v1.3.14`

---

## 3. GitHub Releases

Create a **GitHub Release** based on the `v1.3.14` tag. This provides:

- A downloadable `.zip` of the source code.
- A public record of what changed in the 1.x era.
- A clear "Starting Point" for 2.0.

---

## 4. GitHub Issues & Milestones

Instead of just a single document, we should break the `upgrade_proposal.md` into actionable **Issues**.

1. **Create Milestone**: "v2.0 Launch".
2. **Create Issues**:
    - [ ] [v2.0] Implement 15-level difficulty logic (#ID1)
    - [ ] [v2.0] Add POS-based distractor generation (#ID2)
    - [ ] [v2.0] Implement "Don't Know" button logic (#ID3)
    - [ ] [v2.0] Build level failure indicators on Level Map (#ID4)
3. **Link to Project Board**: Use GitHub Projects to drag and drop these issues (Todo -> In Progress -> Done).

---

## 5. Immediate Next Steps for v2.0

1. **Update `package.json`**: Change version to `2.0.0-alpha.1`.
2. **Update `constants.ts`**: Set `APP_VERSION` to `R.2.0.0`.
3. **Initialize `develop` branch**.
4. **Tag the current state** to preserve history.
